-> CLOSED. An epoch-scoped state root is by definition fresh, so a child launched into it without
   `--resume` lands in gjc's first-run onboarding wizard and never creates a session for the
   gateway to adopt. Reusing a warm shared root instead would abandon the epoch scoping that
   satisfies AC-11. Note this is NOT a defect in the shipped path: there the session is created by
   `session.create` (which does not onboard) and the child always launches with `--resume`, which
   is why the live drill starts cleanly in a fresh epoch root.

############ H. ask gjc for the worktree path instead of replicating it — CLOSED ############
# Route E was rejected because replicating gjc's generated worktree suffix would be vendor
# reimplementation. But replication is not the only way to learn the path: the gateway could
# ASK gjc, bind the session in the directory gjc names, and then forward `--worktree` literally.
# That would satisfy AC-8 as written without inverting the binder invariant, and without the
# `branch_in_use` collision of route D, because gjc would own the worktree it finds.
#
# Checked the surface: gjc 0.15.5 exposes no worktree query. `gjc worktree` and `gjc worktrees`
# both just print the version banner (not subcommands), `--help` lists no worktree command, and
# the only worktree surface is the launch-time `-w, --worktree[=<value>]` flag itself.
#
# -> CLOSED. There is no way to resolve a managed worktree path without launching gjc, so the
#    gateway cannot bind there before spawning.
