## 1. START HERE — reply attribution is off by one (LIVE, unfixed)

**Every reply carries the previous turn's answer.** Proven on the live DB at 07:45–07:47 UTC.
The delivery *ids* are keyed to the correct trigger; the *text* inside them is one turn late.

| trigger (received) | reply it was delivered as | whose answer that text actually is |
|---|---|---|
| `'야'` 07:45:52 | "처리돼서 새 빌드로 올라왔습니다" | the message *before* `'야'` |
| `'오ㅠ이제 그럼 실전이냐'` 07:46:32 | "네 형님, 여기 있습니다 🦞" | `'야'` |
| `'아'` 07:47:01 | "지금부터 실전입니다" | `'오ㅠ...실전이냐'` |

Reproduce (delivery id = `sha256(originKey|triggerMessageId|part)`, so trigger↔reply is provable):

```python

O = 'discord/dm/1468535438498336923/peer=660473980301344768'
tid = lambda m, p=0: 'gw-t-' + hashlib.sha256(f'{O}|{m}|{p}'.encode()).hexdigest()[:32]
# map each delivery back to the trigger it was keyed to, then read the text
```

### Mechanism

1. A turn ends; `markAccepted` clears `#deliveredIds`.
2. The tail re-attaches **cursorless** — look for `tail_gap_nonstrict session=… resync=null` in `daemon.log`.
3. The resync **replays transcript rows from before this turn**.
4. Transcript rows carry **no `opRef`**, so the attribution filter cannot fence them.
5. `bound.lastAssistantText` is overwritten by that stale row.
6. `onTerminal` trusts `bound.lastAssistantText` → the previous answer ships under the current trigger.

This is also the original "같은 말 두 번" (same thing twice): turn N+1 re-delivers turn N's text.

### Fix (both halves; `packages/gateway/src/orchestrator/persona-session.ts`)

1. **Scope tail frames to the turn.** Drop any transcript frame whose `ts` precedes the batch's
   `dispatched_at` (minus a small clock skew, ~2s). A replayed pre-turn row can then never become
   `lastAssistantText`. Frames with a matching `opRef` are already safe; the un-attributed transcript
   rows are the hole.
2. **Make the transcript authoritative at terminal.** Prefer `port.fetchAssistantSince({ notBeforeMs })`
   over `bound.lastAssistantText`, where `notBeforeMs` = runtime `startedAt` ?? `dispatched_at`.
   That method already has the right floor and (since `f2318c8`) returns the full body.

`dispatched_at` (schema 18) is stamped at first bind, **before** the send, and is cleared on requeue —
so it is a safe floor. `accepted_at` is **not** (it can postdate the answer).

### Why today's work missed it

I made the delivery *identity* deterministic (`gw-t-` = trigger+part), which is why the table above
shows correct ids. Identity fixes stop a batch replaying **its own** answer. They cannot stop a batch
sourcing **the wrong text**. The bug is in where the text comes from, not in how it is labelled.

## 3. Owner's canonical redesign (directive, not yet built)

> discord stream → need to deliver? → **steer into the correct session** (send when idle) → reply from that session.
> On steer failure: new session + resume → if that fails, fresh session with last 24h channel context.
> Message edits stream as an update of a `[MESSAGE POINTER]`.

No batch, no settle window, no expiry, no holds, no watchdog.

**Step 1 is on `feat/canonical-steer-pipeline` (`b917425`), NOT merged.** It removes the `nonSteerable`
gag from ingestion and escalates a failed steer to a session rebind. Three tests encode the old
contract and must be **rewritten**, not patched:
- `broker death during a steer leaves the row unconsumed …`
- `slow tail keeps a status-terminal turn non-steerable …`
- `coverage audit leaves a failed steer pending …`

**Step 2 (not started):** delete the batch layer — 115 references, 11 `inboundBatch*` DB methods, the
settle window, `expireStale`, and schema 19 dropping `batch_*` / `accepted_at` / `attributed_op_ref` /
`dispatched_at` / `terminal_delivery_id`. ⚠️ If §1 is fixed using `dispatched_at`, that column must
survive step 2 (or be replaced by an equivalent pre-send stamp).

Sequence: **§1 first** (contained, user-visible, live), then step 1 tests, then step 2.

### Why messages were silently lost (context for step 2)

`expireStale` deletes rows `WHERE state='pending' AND batch_state IS NULL AND received_at <= floor`
— exactly the messages the model **never saw** — and `maxInboundAgeMs` defaults to **10 minutes**.
So anything queued behind a wedge longer than 10 min was destroyed (4 DMs lost behind an 85-min wedge).
Chain: hold → `nonSteerable` → can't steer → stays unbatched → expiry deletes it.

## 4. Turn routing: measured, not a bug

Consecutive messages each opening their own turn is **correct** under the current rule
(`running → steer`, `idle → send`). Turns now complete in 7–21s, so the next message usually lands on
an idle session. Verified: `'아'` replied at 07:47:11, `'그렇냐'` arrived 07:47:38 — 27s after the turn
finished. Separate turns do **not** lose context (the session is persistent).
If burst-coalescing is wanted, that is a deliberate product choice with a latency cost — decide it
separately from the canonicalization.

## 5. gjc 0.16.0 facts (verified, save yourself the time)

- **`tool_activity` never arrives on `gjc sdk serve --stdio`.** The host gates it behind a *negotiated*
  capability and only `websocket-transport.ts` implements negotiation. Zero `tool_activity` frames in a
  full day of live traffic. Writing `event_replay` to stdin does nothing (removed). Real tool/token
  counters require streaming over the **broker WebSocket** instead of the stdio relay.
- `session.list` with a `limit` smaller than the session count pins a continuation cursor
  (`SESSION_LIST_MAX_CURSORS = 32`, TTL 15 min). Never paginate from a periodic probe.
- Broker discovery: `<agentDir>/sdk/broker.json` = `{url, token, pid, incarnation, heartbeatAt}`,
  `BROKER_HEARTBEAT_TTL_MS = 15_000`. WS open → `{type:"broker_hello",protocolVersion:3}`.
- `session.list` input `{scope:{kind:"all"}}` is **invalid**; omit `scope` (must be a `ScopeRequestV1`).
- The recovery decision table (`packages/subsession/src/recovery.ts:87`) holds *any* `terminal_uncertain`
  / `unknown` op with "do not resend, resume or recreate". Correct for a worktree lane; for a chat turn
  it bricks the conversation, because an epoch admits one nonterminal trigger.
